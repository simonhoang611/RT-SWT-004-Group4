\begin{abstract}
Large language models can draft behavior-driven development (BDD) scenarios, but valid syntax does not guarantee preserved business intent. We evaluate GPT-5.4-mini on reconstructing 261 project-maintained Gherkin files from Sylius, Apache Fineract and Diaspora from user stories reverse-engineered from them, with one same-project example per prompt. We measure parser compliance with behave and skeleton cosine similarity to the reference. Excluding the three prompt exemplars ($N = 258$), 255 files (98.8\%, 95\% CI [96.6\%, 99.8\%]) are valid Gherkin, above the 80\% threshold ($p < 0.001$). The median similarity is 0.853; a one-sided exact sign test does not show that it exceeds the proposal's 0.85 reference point ($p = 0.209$, $\delta = 0.054$). Only the e-commerce project exceeds it; the decision changes at 0.84. In an exploratory audit of 60 high-similarity files, 25 contain a business-logic defect (AI-drafted, human-reviewed labels; $\kappa = 0.571$ and $0.609$ against an independent rater), and seeded defects barely change the score. In a same-time rerun, removing the example lowers the median to 0.811, while another exemplar moves single files in both directions with no detectable average effect. Within this reconstruction setting, GPT-5.4-mini is a drafting aid whose business logic needs human review, and embedding similarity alone cannot certify generated Gherkin.

\keywords{Large language models, Gherkin, Behavior-driven development, Acceptance testing, Software testing, GPT-5.4-mini}
\end{abstract}
