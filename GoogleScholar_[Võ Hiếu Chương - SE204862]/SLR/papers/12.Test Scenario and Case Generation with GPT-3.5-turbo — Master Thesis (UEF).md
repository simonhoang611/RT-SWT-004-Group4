## 2.1.1. Software Testing 

What is software testing and why is it very important in the first place. Software testing is a continuous methodical process for assessing the quality level of a software application by performing a set of test activities in order to identify and fix defects that may emerge before the release of the application. It is an activity which is performed by software testers and developers to ensure that software development is done with quality in mind. 

Software testing involves the systematic process of evaluating a software application to identify defects or inconsistencies, ensuring that it functions as intended and meets user requirements (Jain, 2024). Islam, Khan, Alam & Hasan (2023) stated that software testing has a crucial role in software engineering as it is essential for ensuring the quality, performance, security and reliability of software systems. These activities are done to ensure that the application meets requirement and also functions correctly.  The main goal of software testing is to ensure high-quality and reliable software product is delivered to the intended users. In addition, software testing is an aspect of quality assurance. According to Jain (2024), quality assurance encompasses the establishment of quality standards, process improvement initiatives, and adherence to best practices throughout the development lifecycle. 

## _Types of Software Testing_ 

There are five different types of software testing and these are arranged in a hierarchical pyramid form. The arrangement typically follows a bottom-up flow where most of the testing that are fast and less resource intensive are done at the bottom and slower and more complex test are done at the top. 

3 

The test pyramid emphasizes on having a large number of tests at the lower level and, as development moves to the upper levels, the number of tests decreases (Kulkarni, 2018). At the bottom of the test pyramid is unit test followed by component test, integration test, end-to-end/system test and finally, manual test which are all performed in a particular order (Hyette, 2023). ## Unit test 

Unit test is written for all the methods and functions in the code to make sure that the software application is working correctly at the lowest level (Hyette, 2023). The target of a unit test is to test every single line of code in a method, this helps to improve the code coverage. Code coverage refers to the percentage of code executed during testing. It is always a good practice to opt for 100% of code coverage (Ochieng, 2023). 

## Component test 

Sometimes, unit test will not be enough to consider the application as fully tested. Component testing ensure that a complete section of an application is tested. A typical web application will consist of at least three components, frontend, database and the API backend (Hyette, 2023). A component test, for example will test the API backend in isolation from all the other components. In such instance, all the dependencies of the component under test will be mocked. Mocking in software testing involves creating 

4 

mock objects that simulate the behaviour of real objects (khankhoje, 2024). The mock object behaves like the real one but is controlled within the testing environment. The purpose of component test is to ensure that the componentâ€™s functionality works as it is intended without the interference of the other components. This helps to test the component in very specific conditions. It also ensures that the units the makes up the components work well in unison. 

## Integration test 

Integration test is need to test how well the components work together. It does not have to be a test that test the entire application but rather just the components that makes up the application (Hyette, 2023). There are two type of integration test. These are white-box testing and black box testing. 

## End-to-end/System test 

End-to-end test are sometimes done through automation. For a web application, tools like selenium, cypress, playwright and others are used to test the application where various functionalities are tested automatically with a browser to ensure that everything works as expected. End-to-end test consist of testing technique like functional testing which ensure that for example the application loads with the correct content or the login works and acceptance testing in a form of Behaviour Driven Development specification which ensures that the application meets business requirement and others techniques like performance, regression and security testing (Hyette, 2023). End-to-end test ensure that all the components of the application works perfectly together. End-to-end test are sometimes written in the gherkin language which follows the GIVEN WHEN THEN pattern which is supported by frameworks like cucumber, specflow and others. The downside to end-to-end test is that it takes really long time to execute, very brittle and flaky as it can easily breaks when one component response slower than expected. Some frameworks that allows error logs to be record or screenshot to be taken when a test fails, this helps to know what caused the failure. 

## Manual test 

Manual test is done to test functionalities that are too complicated to automate or not very necessary or critically worth the time automating (Hyette, 2023). In an ideal case it is worth automating all test. The down side to manual testing is that it is difficult to fix bugs

## _Transformer_ 

A transformer is a neural network that learns context and thus meaning by tracking relationships in sequential data. Transformers uses a sequence-to-sequence architecture (Merritt, What Is a Transformer Model?, 2022).  It takes a text sequence as input and produces another text sequence as output thus It transforms an input sequence into an output sequence (Williams, 2024). It is a neural network that transforms a given sequence of words in a sentence into other forms of sequences with the help of an encoder and a decoder (Maxime, 2019). This type of model architecture performs well at language translation task. Transformers follows a sequence-to-sequence way of learning. Transformers has proven to be one of the most effective neural network models used for NLP tasks. Figure 3 represents the architectural structure of a transformer. 

16 

Figure 3: The transformer Architecture model (Vaswani, et al., 2017) 

Transformers consist of mainly an encoder and a decoder. The encoder is represented on the left side and the decoder on the right side of the figure above and both consists of multiple modules which can be stacked on top of each other. These modules are composed of mainly Multi-Head Attention, Feed Forward layers and others. 

The encoder works on the input sequence and the decoder works on the target output sequence. The encoder helps to process and prepare the input data by understanding its structure. It starts by taking a sequence of words, for example words in a sentence and predicts the next word in the output sequences or translate these words into other language. These words are represented as sequence of tokens. (Williams, 2024) Tokens are chunks of text which have meaning. The sequences of tokens are converted into some numerical vectors commonly refer to as embeddings. These embeddings store the 

17 

context of each token. The embeddings enable the model to understand the intricate relationship between the token and also help the model to process textual data mathematically. Tokens with similar meaning have similar embeddings. Positional embedding is one of the important parts of this model as it is responsible for assigning each token in the sequence a relative position. 

This helps the model to understand the position of a token within a sequence to ensure that the order and relative positions of tokens are understood and considered during processing (Williams, 2024). These relative positions are added to the embedding representation of each word. In summary, the encoder follows an iterative process in the encoding layer where the encoder generates encodings that define which part of the input sequence are relevant to each other and then return these encodings to the next encoder layer. The encoder consists of two mechanisms which are self-attention and feed-forward mechanism. 

Self-attention is a key mechanism used in transformers, which allows the model to focus on different parts of the input sequence when processing each element (Verma, 2023). Feed-forward is a mechanism that allows the model to learn complex patterns and relationships in the data (Gomez, 2023). It takes the output of the self-attention mechanism and transforms it into the final output by refining the understanding of each word to ensure that subtle nuances are accurately captured thus helps to optimize the learning process. 

The decoder takes all the encodings and uses their derived context to generate the output sequences. In conclusion, transformers are a form of semi-supervised learning where it starts by pre-training the model in an unsupervised manner with a large, unlabelled dataset and then they are later fine-tuned in a supervised manner to ensure they perform well. The main catch that makes transformers perform better is something called an attention mechanism which are explained above. This helps to provide context around items in the input sequence. ## _Fine Tuning_ 

This involves taking raw general-purpose AI model and customizing them for a specific use case. An example use case will be to fine tune an existing LLM to be able to take incident bug of reported functionality issues of an application and also be able to make conversations and provide answers to questions about the related bugs and finally be able to log, store and report these bug issues into a ticket for the associated individuals to handle or fix.

It basically allows LLMs to look up information outside of the data that the LLM was originally trained on (Berman, 2024). This is mostly used for customizing models to enable a high degree of control and flexibility of the modelâ€™s output. Prompt engineering can be done by carefully designing prompts to instruct the model to produce responses from its learned knowledge in a way that aligns with the desired output. Some techniques used in prompt engineering are zero-shot prompting, few-shot prompting, chain of thought reasoning and others. Zero-shot prompting leverages on pre-trained modelâ€™s understanding of words and concepts relationship without further training whiles few-shot prompting enhances the model with explicit training examples through the input prompt without needing to retrain.

## Test Driven Development 

TDD approach is one of main software development practice for the case company. TDD is a set of techniques that any software engineer can follow, which encourages simple designs and test suites that inspire confidence (Beck, 2002). It is a practice in software development that focuses on an iterative development cycle where the emphasis is placed on writing test cases before the actual feature or function is implemented.  It is a software development process that involves writing tests for your code before writing the implementation code (Schmitt, 2024). TDD usually focuses on testing smaller pieces of functionality in isolation. TDD follows the "Red-Green-Refactor" cycle (Stevens, 2019). Figure 8 illustrates the flow of TDD process.

## Behaviour Driven Development 

BDD is often misunderstood, but itâ€™s merely the evolution of TDD (Stevens, 2019). BDD practice follows a collaborative practice that allows software teams, business people and other stakeholders to communicate efficiently on a feature or a task in order to establish a shared understanding and come up with concrete examples of desirable functionality for that feature. This practice provides a discussion point to brainstorm ideas related to the task on how to formulate an effective solution. The outcome of this practice produces a system documentation in a form of BDD specification which should be easily understandable to everyone. 

This practice is often done before starting the actual feature implementation. BDD follows a rapid small iterative step. This is done to facilitate quick feedback. Additionally, following BDD practice helps to guide the testing of a software based on the behaviour the software exhibit to a user. This helps to drive the thinking process of testing a software from the perspective of someone or something that is using the software. BDD test focuses more on the results of the higher-level scenario (Stevens, 2019). In summary, BDD starts with a task, usually a vague one. The task is about some wish that a user wants to achieve. An example will be â€œ _A bank customer want to send and withdraw money_ â€. A user story is created to represent the wish/task that the user wants, which is written in a precise manner. An example user story from the above example task is presented below: 

## **As a** bank customer 

## **I want** to be able to send and withdraw money 

## **So that** I can be able to sustain my life and businesses 

After this, concrete examples are formulated from the user story. These examples are called the acceptance criteria. These are more specific than the user story. They contain specific scenarios that are used to capture the specification of the feature (Stevens, 2019). These example acceptance criteria are described using a domain-specific language, such 

38 

as Gherkin, which is stored as a feature file. An example acceptance criterion using cucumber language with Gherkin syntax is below: 

**Feature** : Money Transfer and Withdrawing 

**Scenario** : Adult User Sending and Withdrawing Money 

Given a user is an adult 

And the user has a balance of 50 euros 

When the user withdraws 30 euros 

Then the user should be able to withdraw successfully 

After that, these acceptance criteria are translated into executable specification. This consists of implementing the test scenarios and cases that makes up the acceptance criteria. Usually, developers write these acceptance criteria into an actual executable specification test. There are multiple frameworks and programming languages that can be used to achieve this. For example, cucumber test for Java, JavaScript, Cypress and playwright for JavaScript and many others. The cycle ends when these executable specification passes. (Stevens, 2019) Some benefits of BDD are that, it helps to bridge the gap between business and technical teams which in turn helps to reduce any confusion about acceptance criteria. It also helps to identify potential problems with user stories. Moreover, it ensures that the application functions correctly according to end userâ€™s expectation. 

There are a lot more that comes with BDD. The above demonstrated definitions and examples is just an aspect of BDD. The main take away is that BDD helps to introduces quality into the design of a software. BDD and TDD play well together as BDD ensures that all stakeholders align on the vision, TDD provides a way for the developers to get there to accomplish the vision (Khan, 2023). 

## Mob Programming 

Since the main software development method is mob programming, all the team members are involved in testing and development process and work together in real time, on one task and one computer. Mob Programming is a style of programming in 

39 

which the entire team sits together and works on a single task at a time using the same computer and other devices (Maaret & Llewellyn, 2018). Mob programming takes advantage of a groups collective knowledge to complete a task, but also promotes the development of soft and hard skills. 

Mob programming originated from agile software development practices. The main advantage of mob programming is that, it utilizes the groups collective knowledge and understanding to complete a task, but also promotes the development of soft and hard skills. In mob programming, there is usually a large monitor or projector that ensures everyone on the team can see the code. The mob strategy uses a driver-navigatorfacilitator workflow. Participants rotate through various roles. The navigator is responsible for listening to the mob and passing down instructions to the driver. The driver is the only person behind the keyboard and responsible for converting the navigatorsâ€™ instructions into code. The facilitator is responsible for keeping the mob on track and deciding when to switch roles.

## 6.1 Summary of LLM customization techniques 

Prompt Engineering approach involved designing and refining prompts to direct the AI model in generating relevant and high-quality test scenarios and cases. It also involves crafting precise and effective inputs to elicit the desired responses from AI models. We discovered that carefully crafted prompts significantly impact the relevance and accuracy of the generated outputs. 

By iteratively testing and refining prompts, we were able to achieve a balance between specificity and flexibility, enabling the model to produce diverse and pertinent test cases. In the context of software testing, this technique is pivotal for generating relevant test scenarios and cases. By designing prompts that encapsulate specific testing requirements and edge cases, testers can harness <mark>GPT-3.5-turbo [GAP 1]</mark> to produce comprehensive and targeted test scenarios and cases. 

For instance, a well-engineered prompt might ask the model to generate test cases for a login feature with various user roles and permissions. The specificity of the prompt ensures that the generated test cases cover a wide range of scenarios, including typical usage, boundary conditions, and potential failure points. This approach not only saves time but also enhances the thoroughness of the testing process, leading to more robust software. However, the challenge lies in crafting prompts that are both comprehensive and concise. Overly complex prompts can confuse the model, leading to irrelevant or redundant test cases. Conversely, overly simplistic prompts may not capture the nuanced scenarios necessary for thorough testing. Thus, achieving the right balance is crucial and requires a deep understanding of both the software being tested and the capabilities of the AI model. 

Fine-tuning involves adjusting the AI model on domain-specific data to improve its accuracy and relevance for particular tasks. In software testing, fine-tuning <mark>GPT-3.5-turbo [GAP 1]</mark> on historical test scenarios and cases, domain-specific requirements and others can significantly enhance its ability to generate pertinent test scenarios and cases. By 

86 

exposing the model to a curated dataset of past testing experiences, it can learn to recognize patterns and anticipate potential issues that are specific to the domain. 

For example, a fine-tuned model for a financial application might better understand the intricacies of financial transactions, regulatory compliance, and security concerns, leading to more relevant and high-quality test scenarios and cases. The benefits of fine-tuning are substantial. It allows the AI model to move beyond generic responses, offering nuanced insights that align closely with the specific needs of the software under test. However, this process also demands a considerable amount of high-quality, domainspecific data, which can be challenging to obtain. Moreover, fine-tuning requires iterative experimentation to avoid overfitting, where the model becomes too tailored to the training data and loses its generalization capabilities. 

RAG methodology incorporated external knowledge sources to support and enhance the AI modelâ€™s responses. By integrating a retrieval mechanism, the model could access and utilize a broader context, resulting in more comprehensive and informed test scenarios. This hybrid approach demonstrated how combining generative capabilities with retrieval systems can overcome limitations of standalone generative models, offering a more robust solution for complex testing environments.
