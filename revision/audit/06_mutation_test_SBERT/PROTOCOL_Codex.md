This is a **test of the metric's sensitivity to synthetic transformations**, not GPT's actual defect rate. M_NUM changes every number; M_PARAM changes every string in double quotes, so it may only rename a fixture consistently. It must not be assumed by default that every mutant is wrong in business terms. The column `above_threshold_pct` means that the cosine is still ≥0.85; it does not automatically mean a false negative on a defect confirmed by an expert.

Limitations found before the run: the extract function drops the Background and does not check parser/baseline E1–E4; the operators that delete/move steps do not carry along the attached table/docstring. The original H3 always passes `has_background_context=True`; so it skips W2_NO_CONTEXT, and the detected column counts only ERROR, not warning. These problems are not fixed, in order to preserve the reproduction; instead, the following are recorded separately: the parser result for original/mutant, the H3 codes, the dropped Background, the number of baselines with errors, and a table for the parser-valid/baseline-no-hard-error pairs. The initial sample stays at 120; subset analyses must report the real denominator and must not replace it with another sample.

Model: sentence-transformers/all-MiniLM-L6-v2, with the revision pinned in `model_run_metadata.json`; CPU, float32, eval, normalized embeddings, default max_seq_length=256. The dot product of the two normalized vectors is compared, which is equivalent to cosine (float32 error can take it slightly above 1). Whether original/mutant have the same skeleton is checked directly, not only inferred from the cosine.

All results are saved, including parse errors, under `results_audited/`. Report both the proportion [0,1] and the name of the column that holds the real percentage [0,100]. Do not call the parser or ordering checks running tests on the software/step definitions.
