## B3: the 0.85 threshold

**Sensitivity to the threshold** (`b3_threshold_sweep.csv`, all projects):

| t | n ≥ t | Share ≥ t (95% CI) | Median − t | Wilcoxon p (one-sided, > t) |
|---|---|---|---|---|
| 0.80 | 202 | 78.3% [72.8, 83.2] | +0.053 | 3.1e-22 |
| 0.83 | 160 | 62.0% [55.8, 68.0] | +0.023 | 3.0e-06 |
| 0.84 | 153 | 59.3% [53.0, 65.4] | +0.013 | 0.0097 |
| **0.85** | 136 | 52.7% [46.4, 58.9] | +0.003 | **0.474** |
| 0.86 | 112 | 43.4% [37.3, 49.7] | −0.007 | 0.988 |
| 0.88 | 79 | 30.6% [25.1, 36.6] | −0.027 | 1.000 |
| 0.90 | 57 | 22.1% [17.2, 27.7] | −0.047 | 1.000 |

Interpretation:
- The conclusion "scores are above the threshold" is statistically significant only when t ≤ 0.84. At exactly 0.85, the median is only 0.003 higher and p = 0.47.
- By project, the share ≥ 0.85 is Sylius 77.8%, Fineract 34.3%, Diaspora 41.7%. At every t from 0.80 to 0.90, Sylius is always the highest.

**Comparison with the defect evidence.** The threshold cannot be calibrated with the data we have, for three reasons:
1. **The 60-file audit only took files with cosine ≥ 0.85**, by design. So the defect rate of files *below* the threshold cannot be estimated.
2. **Within the ≥ 0.85 group, 25/60 files still have business-logic defects.** These are labels drafted by AI and reviewed by An; κ with Hoàng is 0.571. Cosine **does not distinguish** files with defects from files without defects: Mann–Whitney p = 0.21, AUC = 0.40.

   | Cosine band | Files with defects |
   |---|---|
   | 0.85–0.875 | 11/24 |
   | 0.875–0.90 | 10/16 |
   | ≥ 0.90 | 4/20 |

3. **Mutation test:** all 623 pairs with an injected defect gave cosine ≥ 0.90 (the lowest was 0.900). No threshold in the range 0.80–0.90 caught any defect. At t = 0.95, 97.9% of the pairs still get through. The two types M_NUM and M_PARAM always give cosine = 1, by the definition of the skeleton.

**How to write it in the paper:** treat 0.85 as a descriptive marker of structural similarity, not as a threshold for "business correctness". Report the sensitivity table and lower the level of the claim, as the Action Tracker allows ("soften claims if no calibration").

## H1: results by domain

Numbers come from `h1_domain_table.csv`.

| Project | N | Median (IQR) | ≥ 0.85 | p (> 0.85) | p (< 0.85) |
|---|---|---|---|---|---|
| Sylius | 99 | 0.887 (0.076) | 77.8% [68.3, 85.5] | < 0.001 | 1.000 |
| Fineract | 99 | 0.826 (0.062) | 34.3% [25.1, 44.6] | 1.000 | < 0.001 |
| Diaspora | 60 | 0.831 (0.087) | 41.7% [29.1, 55.1] | 0.992 | 0.008 |

- Kruskal–Wallis: H = 60.87, df = 2, p = 6.1e-14, η²_H = 0.231 (ε²_R = 0.237). [Corrected 16 Oct: the previous version called 0.231 ε², but the formula (H − k + 1)/(n − k) is η²_H.]
- Pairwise comparisons (Mann–Whitney, Holm correction): Sylius differs from Fineract (p = 3.7e-13) and from Diaspora (p = 7.8e-08). Fineract and Diaspora do not differ (p = 0.74).

**Conclusion:** only Sylius is above 0.85. Fineract and Diaspora are **below** 0.85, with statistical significance. So no general conclusion may be drawn from the pooled median.

## B1: leakage from reverse-engineering the user stories (proxy measure)

Correction (19 Oct 2026): the table below has been updated to the corrected `b1_leakage_proxy.py`, which unescapes the line breaks of the reference files before tokenising (see `paper_revised/CHANGES_rev.md`, Corrections). The values of 16 Oct were: pooled 0.41, Sylius 0.28 (p 0.006, more precisely 0.0055), Diaspora 0.31 (p 0.015), Fineract 0.11 (p 0.26).

Numbers come from `b1_spearman.csv`. Measure: the share of the GT's 3-word sequences (trigrams) that also appear in the story, compared with the skeleton cosine.

| Group | Spearman ρ | p |
|---|---|---|
| Pooled | 0.43 | < 0.001 |
| Sylius | 0.29 | 0.003 |
| Diaspora | 0.33 | 0.009 |
| Fineract | 0.11 | 0.30 |

Interpretation:
- In 2/3 projects, the more of the GT's phrases a story contains, the higher the score. This is consistent with the hypothesis that part of the score comes from the story carrying over the GT's wording. This is a **correlation**; it cannot prove a causal relationship.
- The pooled figure is mixed with a project effect: Sylius is high on both quantities.
- The Fineract stories were generated from the first 15,000 characters of the GT, and the GT is very long. So for Fineract the share, computed over the GT, is low.
- There is no external backlog set. **How to write it in the paper:** report this measure together with its limitations, and narrow the claim about external validity.

## H2: how to run it (Hoàng's task, needs an API key)

The script `RBL-to-commit/revision/h2/h2_run_prompts.py` has been checked with a fake client: the prompts are built correctly, logs are written, and it can continue after being stopped. The script keeps the model, temperature, system message, prompt wording and output cleaning of the original run unchanged. Only the examples in the prompt change:
- **C1:** no examples.
- **C2:** uses exemplars 86 / 119 / 203, drawn with seed 2026 before the run.

Run from the root of the `RBL-to-commit` repo:

```
pip install openai
set OPENAI_API_KEY=...        (PowerShell: $env:OPENAI_API_KEY="...")
python revision/h2/h2_run_prompts.py --condition C1 --ids 1,101,201
python revision/h2/h2_run_prompts.py --condition C2 --ids 1,101,201
```

If the 3 trial lines come out `OK`, run everything (the command automatically skips the ids that are already done):

```
python revision/h2/h2_run_prompts.py --condition C1
python revision/h2/h2_run_prompts.py --condition C2
```

Notes:
- Each condition consists of 261 API calls, at least 1 second apart.
- The Fineract exemplar of C2 (id 119) is about 30,000 characters long, so the C2 prompt for Fineract is longer and costs more than C0.
- Do not paste the key into a file and do not commit the key.
- When finished, send back the `revision/h2/` folder (output, logs, config). I will compute the cosine, and An will build the syntax table.
